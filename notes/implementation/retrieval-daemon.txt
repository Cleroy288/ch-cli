================================================================================
DESIGN DECISIONS
================================================================================

1. Unix Sockets vs TCP
   - Chose Unix sockets for security (no network exposure)
   - Better performance for local IPC
   - Platform: macOS/Linux only (Windows would need named pipes)

2. JSON Protocol
   - Line-delimited JSON for simplicity
   - Easy debugging with standard tools
   - Trade-off: slight overhead vs binary protocol

3. Daemonization Approach
   - Using subprocess spawning instead of fork()
   - Cleaner on macOS, avoids fork() issues with ML libraries
   - PID file for lifecycle management

4. Auto-start on First Request
   - Daemon starts automatically when needed
   - Reduces user friction
   - Trade-off: first request takes 5-10 seconds

================================================================================
IMPLEMENTATION DETAILS
================================================================================

Protocol (protocol.rs)
----------------------
- DaemonRequest enum: Embed, Rerank, Expand, Status, Shutdown, Ping
- DaemonResponse enum: Embeddings, Scores, SearchSpec, Status, Ok, Pong, Error
- Serde JSON serialization with newline delimiter
- Unit tests for serialization roundtrip

Lifecycle (lifecycle.rs)
------------------------
- start_daemon(): Spawns subprocess, writes PID file
- stop_daemon(): SIGTERM then SIGKILL after timeout
- daemon_status(): Reads PID file, checks process exists
- Uses nix crate for signal handling

Server (server.rs)
------------------
- ModelDaemon struct holds loaded models
- Non-blocking socket listener with shutdown flag
- Currently placeholder model implementations
- TODO: Integrate actual Candle models in Phase 1B

Client (client.rs)
------------------
- DaemonClient with auto-start capability
- Connection timeout handling
- Methods: embed(), rerank(), status(), ping(), shutdown()

================================================================================
FILE LOCATIONS
================================================================================

Socket: ~/.rustean/ml.sock (or ProjectDirs fallback)
PID: ~/.rustean/daemon.pid
Models: ~/.rustean/models/

Using `directories` crate for platform-specific paths.
