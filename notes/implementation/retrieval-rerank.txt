================================================================================
DESIGN DECISIONS
================================================================================

1. Cross-Encoder Model Choice
   - Chose BAAI/bge-reranker-base for good balance of quality/speed
   - ~278M params, ~1.1GB memory
   - Alternatives: bge-reranker-large (better but slower)

2. Scoring Approach
   - Process (query, document) pairs through BERT
   - Use [CLS] token embedding -> linear classifier -> sigmoid
   - Output: relevance probability (0-1)

3. Integration Strategy
   - Reranker loaded in daemon alongside embedder
   - Fallback to position-based scores if model not loaded
   - Score documents in batch for efficiency

4. Candidate Expansion
   - Fetch 3x limit from hybrid search when reranking
   - More candidates = better chance of finding relevant results
   - Reranker filters down to best matches

================================================================================
IMPLEMENTATION DETAILS
================================================================================

BgeReranker (cross_encoder.rs)
------------------------------
- Loads BERT model with classification head
- Tokenizes (query, document) pairs with [SEP] separator
- Forward pass: tokens -> BERT -> [CLS] -> linear -> sigmoid

Key methods:
- score(query, document) -> f32
- score_batch(query, documents) -> Vec<f32>
- score_pairs(pairs) -> Vec<f32>

Daemon Integration (server.rs)
------------------------------
- Reranker loaded in load_models() alongside embedder
- DaemonRequest::Rerank handled with actual model
- Fallback: 1/(rank+1) scores if model unavailable

Search Integration (commands.rs)
--------------------------------
- Added --rerank flag to Search command
- rerank_results() function calls daemon
- Documents formatted as "{kind} {name} {signature}"
- Results sorted by rerank score, truncated to limit

================================================================================
CLASSIFIER HEAD LOADING
================================================================================

BGE reranker weights use different naming conventions:
- Tried: "classifier.weight", "score.weight", "cls.predictions..."
- If not found: random init with warning (needs fine-tuning)

Weight loading code:
```rust
for (w_name, _b_name) in weight_names.iter().zip(bias_names.iter()) {
    if let Ok(linear) = candle_nn::linear(hidden_size, 1, vb.pp(...)) {
        return Ok(linear);
    }
}
// Fallback: random initialization
```

================================================================================
KNOWN ISSUES
================================================================================

1. Classifier weight names vary
   - Different BGE versions use different names
   - Fallback to random init may give poor scores

2. No caching of rerank scores
   - Same query/doc recomputed each time
   - Could cache for repeated queries

3. Document truncation
   - Long signatures truncated at 512 tokens
   - May lose important context
