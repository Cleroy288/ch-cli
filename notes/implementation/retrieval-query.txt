================================================================================
DESIGN DECISIONS
================================================================================

1. LLM Model Choice
   - Chose microsoft/Phi-3-mini-4k-instruct
   - 3.8B params, ~4GB memory
   - Good balance of quality vs resource usage
   - 4k context window sufficient for queries

2. Prompt Engineering
   - Structured JSON output format
   - Clear instructions for symbol extraction
   - Intent categorization
   - File filter suggestions

3. Fallback Strategy
   - Heuristic parsing when LLM unavailable
   - CamelCase/snake_case word extraction
   - Keyword-based intent detection
   - Graceful degradation

4. Integration Approach
   - QueryInterpreter wraps LLM
   - Daemon handles Expand requests
   - Automatic fallback if model fails

================================================================================
IMPLEMENTATION DETAILS
================================================================================

Phi3Model (llm.rs)
------------------
- Uses candle-transformers phi3 module
- Loads weights via memory-mapped safetensors
- Autoregressive text generation
- Configurable max tokens (default 256)

Key methods:
- from_model_id(id) -> load from HuggingFace
- generate(prompt, max_tokens) -> generated text
- expand_query(query) -> JSON response

QueryInterpreter (interpreter.rs)
---------------------------------
- Wraps optional Phi3Model
- interpret() uses LLM if available
- Falls back to heuristic parsing
- Returns SearchSpec

Parsing Utilities (mod.rs)
--------------------------
- parse_intent(str) -> QueryIntent enum
- parse_llm_response(query, json) -> SearchSpec
- fallback_parse(query) -> SearchSpec

================================================================================
FALLBACK HEURISTICS
================================================================================

Symbol extraction:
- Split query on whitespace
- Keep words with uppercase or underscore
- Filter common English words

Intent detection by keywords:
- "where", "definition" -> FindDefinition
- "used", "calls", "references" -> FindUsages
- "how", "what", "explain" -> Understand
- "fix", "change", "modify" -> Modify
- "bug", "error", "debug" -> Debug
- default -> Search

================================================================================
KNOWN ISSUES
================================================================================

1. Large model size
   - ~4GB memory for Phi-3
   - May fail on low-memory systems
   - Fallback provides degraded experience

2. Latency
   - 200-500ms per query expansion
   - Not suitable for real-time autocomplete

3. JSON parsing fragility
   - LLM may produce invalid JSON
   - Fallback handles this gracefully

4. Context window
   - 4k tokens may truncate long queries
   - Usually sufficient for code search
