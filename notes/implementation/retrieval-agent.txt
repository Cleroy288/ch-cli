DESIGN DECISIONS
================================================================================

1. Pipeline Architecture
   - Single RetrievalPipeline class orchestrates all steps
   - Lazy initialization (index on first query)
   - Caches symbols, graph, and search index
   - Configurable steps via PipelineConfig

2. Feedback Loop Design
   - Separate FeedbackLoop class wraps pipeline
   - Maintains history of outputs
   - Max iterations to prevent infinite loops
   - Text parsing for CLI/LLM-driven feedback

3. Output Format
   - XML for LLM consumption (consistent with context expansion)
   - Human-readable summary for CLI
   - Token count estimation for budget management

4. CLI Integration
   - New `retrieve` command for full pipeline
   - Flags to disable individual steps
   - --xml flag for raw output

================================================================================
IMPLEMENTATION DETAILS
================================================================================

RetrievalPipeline (pipeline.rs)
-------------------------------
- Holds IndexManager result (symbols, graph)
- Holds HybridSearch instance
- Holds DaemonClient for ML operations

Key methods:
- initialize() -> index project, build search
- retrieve(query) -> full pipeline execution
- get_more_context(symbols) -> expanded context

Pipeline steps:
1. Query expansion via daemon (or skip if no_expand)
2. Hybrid search with configurable limit
3. Reranking via daemon (or skip if no_rerank)
4. Context expansion via ContextExpander

FeedbackLoop (feedback.rs)
--------------------------
- Wraps RetrievalPipeline
- Maintains history of RetrievalOutput
- Supports multiple feedback actions
- Suggests next action based on results

Actions:
- MoreContext { symbols } -> get_more_context()
- RefineSearch { query } -> retrieve(new_query)
- ExpandRelated { symbols } -> search for related
- FilterFiles { patterns } -> filtered search
- Accept -> no-op

RetrievalOutput (mod.rs)
------------------------
- query: original query
- search_spec: expanded specification
- xml_output: formatted context
- result_count: number of results
- token_count: estimated tokens
- has_more: pagination indicator

================================================================================
PIPELINE FLOW
================================================================================

1. Initialize (once per session):
   - Index project with semantic analysis
   - Store symbols and graph
   - Build hybrid search index

2. Retrieve (per query):
   a. Expand query (LLM or fallback)
   b. Search (fetch 3x limit if reranking)
   c. Rerank (cross-encoder scores)
   d. Expand context (XML formatting)

3. Output:
   - Human-readable summary + XML
   - Or raw XML with --xml flag
